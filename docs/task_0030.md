# Task 0030: Config presets in the web interface (COMPLETED)

## Description

The web editor can only open a YAML from the user's computer and download it
back (`Open YAML` / `Save YAML`); the server remembers nothing. Users want a
list of ready-made pipeline setups to load in one click (the 16 files in
`configs/`, with short names instead of file names) and a way to save the
current pipeline under a name of their choosing on the server.

This task adds presets: built-in ones from `configs/` (named through a new
manifest `configs/presets.yaml`) and user ones stored as plain YAML files in a
server folder (`--presets-root`, default `_testbed/presets/`). A preset holds
the pipeline only: `source` and `output` are stripped on save and never touched
on load; `device` stays in the preset. Built-ins are read-only.

Design: `docs/superpowers/specs/2026-11-03-config-presets-design.md`.

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Client-supplied name or id reaches the file system outside the presets root (`../x`, absolute path, encoded dots, symlink) | Medium | Names pass through `slugify` and `web.paths.safe_join`; symlinks are rejected; traversal tests on logic and routes |
| A name that slugs to nothing writes a stray file | Medium | `slugify` raises `PresetInvalid`; no file is written; tested |
| One hand-edited invalid user file hides the other presets | Low | It is listed; only loading it reports the error |
| Loading a preset overwrites the user's video or output folder, or invents them on a fresh editor | Medium | `loadPreset` keeps the current `source`/`output` and never creates them; tested |
| Overwriting another preset silently, or a race between two saves | Low | Exclusive create (`x`) and 409 unless `overwrite`; atomic replace via temp file |
| A new config added to `configs/` is forgotten in the manifest | Medium | Manifest test compares the manifest with `configs/*.yaml` |
| Built-in config altered by mistake | Low | Built-ins are read-only (403 on delete, save clashes answer 409) |

## Implementation details

- Backend: `web/presets.py` (no FastAPI import) holds the manifest reader,
  `slugify`, list/read/save/delete. User presets are `<slug>.yaml` with a
  first-line `# name:` comment; saves use exclusive create (409 unless
  `overwrite`) and an atomic replace; `source`/`output` are stripped on save
  and on built-in reads. `configs/presets.yaml` names the 16 built-ins; a test
  fails when a `configs/*.yaml` is missing from it.
- Routes in `web/app.py` (`GET/PUT /api/presets`, `GET/DELETE
  /api/presets/{id}`), `--presets-root` in `web/server.py`,
  `WebPaths.presets_root`; `_split_config` is shared with `/api/config/parse`.
- Front-end: `api/presets.ts` client, `loadPreset` in `editor/yamlState.ts`
  (keeps the editor's `source` and `output`), `presets/` (hook, popover menu,
  save dialog, CSS) wired in `App.tsx`.
- Follow-up fix found in review: known keys sent through `extras` on save are
  validated too.
