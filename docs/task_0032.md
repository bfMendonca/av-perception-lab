# Task 0032: Delete a run from the web history (COMPLETED)

## Description

Runs accumulate under `out_root` (video, CSV, previews) and the only way to
free disk space is deleting folders by hand. This task lets the user delete a
single run from the web interface after a confirmation that shows the space
the run uses. Design: `docs/superpowers/specs/2026-11-03-delete-run-design.md`.

## Implementation details

- `history.run_size` sums regular files without following symlinks;
  `history.delete_run` resolves the id through `run_folder` (or the
  `job-<id>` record logic) and uses `shutil.rmtree`, which unlinks symlinks.
- Routes in `web/app.py`: `GET /api/runs/{id}/size`, `DELETE /api/runs/{id}`
  (204/404/409). `JobQueue.holds_run(folder)` decides the 409.
- Front end: `DeleteRunDialog` (size fetched on open), trash buttons in
  `RunList` and `RunDetail`, `RunsView` refreshes the list, closes the open run
  and removes it from the compare selection. `.runitem__main` right padding was
  raised to 70px so titles clear the compare and trash buttons.
- Final review fixes: `history._is_run` (shared with `scan_runs`) makes
  `run_size`/`delete_run` refuse folders without a run marker (404), so
  `DELETE /api/runs/library` cannot remove a non-run folder; `delete_run` also
  unlinks the `.web_jobs/*.json` records whose `run_dir` is the deleted folder,
  so a failed/cancelled run does not come back as `job-<id>`. The route answers
  500 `could not delete: ...` on `OSError`; the dialog treats 404 as already
  deleted and locks Cancel/Escape while deleting.
- Docs: CHANGELOG, DESCRIPTION and docs/reference.md updated in the same change.

## Test notebook

- [ ] Open the runs view and click the trash button on a finished run's list
  row: the dialog names the run and shows the space it frees. Cancel: nothing
  changes.
- [ ] Delete it for real: it leaves the list and its folder is gone from the
  output directory on disk.
- [ ] Select a run, then delete it from the trash button in the detail panel:
  the panel closes and the URL no longer names it.
- [ ] Open a comparison and delete the comparison run: only the comparison is
  cleared, the main run stays open.
- [ ] Start a job and try to delete its run while it runs: the dialog shows
  "run is still queued or running" and the folder stays.
- [ ] Delete a failed run that has a folder, then reload the page: it does not
  reappear as a `job-...` entry.
- [ ] Delete a failed run that left no folder (`job-...` entry): it disappears
  and `.web_jobs/<id>.json` is gone.
- [ ] Create a non-run folder (e.g. `mkdir <out_root>/scratch`) and
  `curl -X DELETE .../api/runs/scratch`: 404 and the folder is still there.
