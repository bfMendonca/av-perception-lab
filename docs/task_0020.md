# Task 0020: Provisioning engine, sources and `--prepare` (COMPLETED)

## Description

`task_0019` lets every component declare what it needs and computes a
torch-free `ModelStatus`, but nothing can obtain a missing piece yet. This task
adds the framework-free provisioning engine (spec
`docs/superpowers/specs/2026-10-31-model-readiness-design.md`): one `prepare`
call brings a `Requirements` to `ready` by running a registered *source* per
asset kind, and the CLI gets a `--prepare` flag that prepares every component
of a YAML and prints a status table.

Requirements for the engine:

- Downloads are atomic (`<target>.part`, then rename), resumable when the
  server supports `Range`, verified (`sha256` when declared), cancellable
  (a `threading.Event` checked between chunks) and idempotent (a ready model
  is a no-op).
- A failed Prepare ends as `failed` with a readable reason (offline, HTTP 404,
  gated, sha256 mismatch), never a crash; a `UserProvided` asset never triggers
  a download.
- Every write path is confined to the weights root (`contained()`).
- A new source kind is one class plus `register_source`, never an engine edit.
  Google Drive is not implemented (extension point only).

## Planning

### Step 1: Failing tests

Sources: URL download atomic + sha256, resume from `.part` (with and without
`Range` support), sha mismatch removes the `.part`, cancel mid-download, 404 and
offline messages, git clone at the pinned commit (and re-checkout of an
existing clone without deleting it), HF `allow_patterns`/`cache_dir`, gated
message. Engine: no-op when ready, unknown kind fails clearly, a new kind via
`register_source`, `UserProvided` never downloads. CLI: exit code and table,
existing invocations unchanged.

### Step 2: Engine and sources

`prepare` checks first (ready means no source is called), then runs the source
of each non-ready code repo and asset (looked up by class, then by its bases),
collects `ProvisionError`/`OSError` reasons, re-checks and returns a
`ModelStatus` (`failed` with the reasons when any step failed).

### Step 3: CLI

`--prepare` builds the components from the YAML (options validated, nothing
loaded), prepares each with progress on stdout, prints a status table and exits
0 only when every component is ready.

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Truncated / stale `.part` reported ready or accepted on resume | Medium | `.part` is never ready; size and sha256 checked before rename; a mismatch deletes the `.part` so the next run restarts |
| Write outside the weights root | Low | Targets, `.part` and clone folders resolved through `contained()` before any write |
| A cancelled or failed Prepare blocks the caller | Low | Event checked between chunks / while git runs; the git child is killed; errors are returned, not raised |
| Existing clone or weights destroyed | Low | Never delete a clone or a foreign folder; a clone at another commit is fetched and checked out |
| Existing CLI invocations changed | Low | Flag only; test of the existing paths |

## Implementation details

- `core/provision/engine.py`: `Source` protocol (`prepare(asset, root,
  progress(done, total), cancel)`), `register_source(cls)(source_cls)` (a class
  per asset kind or `CodeRepo`; duplicates raise `ValueError`; lookup walks the
  item's MRO, so a subclass of a kind reuses its source), `ProvisionError`,
  `ProvisionCancelled` and `prepare(req, root, progress(label, done, total),
  cancel) -> ModelStatus`. `prepare` returns `check()` unchanged when ready (no
  source runs), prepares code repos first and then assets, skips ready items,
  keeps going after a failed item, re-checks each item after its source ran
  ("still not ready after download" otherwise) and returns `failed` with the
  joined reasons. `ProvisionError`, `OSError` and `ValueError` (unsafe path)
  become reasons; other exceptions are bugs and propagate. A cancel stops at
  once and returns the current `check()` status with a message starting with
  `cancelled` (state `missing`: a `.part` is never ready). The packages layer is
  reported, not installed (`task_0024`).
- `core/provision/sources.py` (stdlib only at import):
  - URL: `urllib`, streams `read1(64 KiB)` into `<target>.part`, checking the
    cancel event before every read. A `.part` is resumed with `Range`; a 206
    with the expected `Content-Range` appends, a 200 rewrites from zero, a 416 or
    a wrong range deletes the `.part` and restarts. An early close keeps the
    `.part` (resume next time). Size and sha256 are checked before the atomic
    `os.replace`; a mismatch deletes the `.part`, so a stale prefix is never
    accepted twice. Only `http(s)://`. Messages: `not found (HTTP 404)`,
    `access denied (HTTP 401/403)` (+ gated hint), `offline or unreachable`.
  - Hugging Face: `huggingface_hub.snapshot_download(repo, revision,
    cache_dir=<root>/<target>, allow_patterns=files+patterns or None,
    tqdm_class=...)`, imported inside `prepare`. The `tqdm_class` is a silent
    subclass of the hub's `tqdm` that forwards the bytes of the
    `huggingface_hub.snapshot_download` bar to `progress` and raises
    `ProvisionCancelled` from `update` when the event is set (the hub's own
    `.incomplete` blobs stay, are never ready and are resumed by the hub). Hub
    errors are mapped by class name (gated -> "gated - accept the licence at
    https://huggingface.co/<repo> and set HF_TOKEN (or run `hf auth login`)";
    `LocalEntryNotFoundError`/offline -> "offline or unreachable"; repository,
    revision, entry not found -> "HTTP 404"); anything else is reported with its
    class name, never raised.
  - git: `git` CLI with `GIT_*` stripped, `GIT_TERMINAL_PROMPT=0` and
    `GIT_ALLOW_PROTOCOL=file:git:http:https:ssh`, `--` before the URL. A new
    clone goes to `_code/<name>.part` (`clone --no-checkout`, `checkout
    --detach <commit>`, fetching the commit if it is not on a branch), then is
    renamed; a failure or cancel removes only that temporary folder. An
    existing clone at another commit is fetched and checked out (untracked
    files survive); a folder that is not a clone is left untouched with a
    readable error. git is polled every 0.1 s and killed on cancel or on any
    exception (Ctrl-C included).
  - User-provided: raises "provide this file: <hint> (expected at <path>, or
    set the option '<option>')"; never touches the network.
- Every write path (`target`, `target + ".part"`, `_code/<name>`,
  `_code/<name>.part`, HF cache dir) goes through `contained()` first.
- CLI: `--prepare` (flag only; existing invocations unchanged) loads the YAML,
  builds detectors, depth, refiners, semantic segmenters and the tracker
  (`config_components`), prepares each with progress lines on stdout (at most
  one per second per item), prints the weights root, a table (component, type,
  state, assets, code, packages) and the reasons, and exits 0 only when every
  component is ready (1 otherwise; configuration errors 2). The video is not
  probed and no model is loaded.
- Deviations: tests were written right after the engine skeleton instead of
  strictly before it (all were run red/green while fixing the fixtures); a
  `--weights-root` CLI option was not added (`DDD_WEIGHTS_ROOT` works; the
  plan puts the option in the web server task). Google Drive is only the
  extension point, as decided.
