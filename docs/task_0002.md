# Task 0002: Pipeline modular com componentes abstratos, configuração YAML e detector YOLO26 (CONCLUÍDA)

## Descrição

O pipeline da `task_0001` funciona, mas é acoplado aos dois modelos testados:
o `cli.py` (639 linhas) constrói diretamente o `Detector` RF-DETR e o
`DepthEstimator` DA3, decide se estima a focal inspecionando nomes de modelos
DA3 (`classify_depth_model`/`peek_model_name`) e lê atributos específicos do
DA3 (`depth.kind`, `depth.repo_id`, `fixed_intrinsics`) para nomear a pasta e
escrever o `metrics.json`. Trocar ou somar modelos exige mexer no laço
principal.

Esta task reorganiza o projeto em **componentes com contratos abstratos**:
cada família de modelo (detecção, profundidade e — planejado — segmentação)
tem uma classe base; cada modelo concreto é um **adaptador** que herda dela,
trata todas as particularidades do framework (formato de entrada, cores,
letterbox, unidades, nomes de classes) e entrega sempre o mesmo contrato ao
pipeline. O pipeline passa a ser agnóstico de modelo e framework, aceita
**vários detectores no mesmo passo** e agrega as inferências.

Para provar a abstração com mais de uma implementação, a task já inclui o
adaptador **Ultralytics YOLO26** (em especial `yolo26*-objv1-150.pt`, treinado
no Objects365, já presente na máquina com GPU).

### Decisões tomadas com o usuário (2026-10-12)

- Escopo: refatoração + adaptadores RF-DETR, DA3 e YOLO + múltiplos
  detectores com agregação `concat`. Fusão (NMS/WBF entre modelos) e
  segmentação ficam para tasks seguintes, mas os contratos já as preveem.
- Configuração: **arquivo YAML** (`--config run.yaml`) descreve o pipeline
  inteiro; exemplos versionados em `configs/`.
- As flags atuais (`--det-*`, `--depth-model`, …) são **substituídas** (sem
  aliases); README e CHANGELOG documentam a nova forma.
- Múltiplos detectores: padrão `concat` — todas as detecções são mantidas e
  marcadas com o modelo de origem (`source`), no CSV e por cor no vídeo.

- `~/dev/ultralytics` @ `9a0f297`, ultralytics 8.4.175 (no venv dele: torch

## Arquitetura proposta

### Contratos de dados (o núcleo do desenho)

Tudo o que cruza a fronteira de um componente é dataclass imutável com numpy,
sem objetos de framework:

| Tipo | Conteúdo | Convenções |
|---|---|---|
| `Frame` | `rgb` (H,W,3) uint8, `index`, `t` | sempre RGB, já rotacionado |
| `Instances` | `xyxy` (N,4), `score` (N), `label` (nome canônico), `raw_label`, `source` (id do modelo), `masks` (N,H,W bool, opcional) | px do quadro, bordas contínuas; máscaras na resolução do quadro |
| `DepthResult` | `depth_m` na resolução nativa, `geometry` (quadro → mapa), `intrinsics`, `sky` opcional | metros ao longo do eixo óptico |
| `FrameResult` | instâncias + profundidade + estatísticas por instância + tempos por componente | entrada das saídas (sinks) |

- Detecção e segmentação de instâncias compartilham `Instances`: um
  segmentador é um detector que preenche `masks`. A distância por máscara de
  instância é da `task_0004` (`mask_depth_stats`); o parâmetro `mask` atual de
  `box_depth_stats` é a máscara de elegibilidade de pixels do mapa (hoje, "não
  céu") e não serve para máscaras de instância.
- A profundidade fica na resolução nativa + geometria (como hoje): reamostrar
  para o quadro custaria tempo e borraria as bordas.

### Componentes (classes base abstratas)

- `Component`: `name`, `load(ctx)` (carga pesada: device, tamanho do quadro,
  intrínsecos), `close()` (libera GPU), `describe()` (pesos, versões,
  resolução → `metrics.json`). Construção só valida a configuração; erros de
  configuração surgem antes de qualquer carga de modelo.
- `Detector(Component)`: `vocabulary`; `__call__` é *template method* na base
  (cronometragem → `_predict(frame)` do adaptador → mapeamento de rótulos e
  filtro de classes → `validate()` do contrato: formas, dtypes, caixas dentro
  do quadro). Cobre também segmentação de instâncias.
- `DepthEstimator(Component)`: `needs_intrinsics`; `__call__(frame) ->
  DepthResult`.
- Refinador de máscaras por caixa (ex. SAM2) e segmentador semântico (ex.
  SegFormer/TwinLiteNet): **não** são declarados nesta task — seus
  contratos e tipos são definidos inteiramente pela `task_0005`
  (consolidação de 2026-10-12).
- `IntrinsicsProvider`: a focal é da câmera, não do DA3. Implementações:
  fixa (YAML `camera.focal_px`), estimada por DA3 any-view (lógica atual,
  carrega-usa-libera) e prevista por quadro (NESTED). O pipeline só resolve
  intrínsecos se o modelo de profundidade declarar `needs_intrinsics`.
- `Aggregator`: `concat` (padrão desta task). NMS/WBF entre modelos e
  harmonização de rótulos entre vocabulários ficam para a task_0003 (escalas
  de score de RF-DETR e YOLO não são comparáveis).
- `FrameSource` (vídeo atual) e `Sink` (`VideoSink` com renderer,
  `CsvSink`, `NpzSink`, `MetricsSink`): o `run()` atual é decomposto.
- Registro: dicionário + decorator `@register("detector", "yolo")`; cada
  adaptador declara uma dataclass de opções (validação + `--list-models`).
  Imports de framework só dentro de `load()` — o ambiente leve, `--help` e os
  testes continuam sem torch.

### Configuração YAML (esboço)

```yaml
source: {video: _testbed/data/IMG_4021.MOV, start: 0, duration: 0, max_frames: 0, stride: 1}
detectors:
  - {type: rfdetr, size: large, threshold: 0.5, classes: driving}
  - {type: yolo, weights: ~/dev/ultralytics/_testbed/weights/yolo26l-objv1-150.pt, threshold: 0.4, classes: driving}
depth: {type: da3, model: da3metric-large, process_res: 504, hf_cache: ~/dev/depth-anything-3/_testbed/weights/hf}
camera: {focal_px: null, estimate: {model: da3-large-1.1, frames: 16}}
aggregation: {type: concat}
distance: {box_shrink: 0.1, outlier: iqr, stat: median, type: z, min_valid_px: 20, exclude_sky: true}
render: {layout: side-by-side, show_stats: true, draw_inner_box: true, max_depth: 30}
output: {out_root: _testbed/outputs, tag: "", save_depth: false}
```

CLI mínima: `det-depth-distance --config run.yaml [VIDEO]` (vídeo posicional
sobrescreve `source.video`), `--set chave.pontilhada=valor` para ajustes
rápidos e `--list-models`. Configs de exemplo em `configs/`
(`rfdetr_da3.yaml` = comportamento atual, `yolo_o365_da3.yaml`,
`multi_detector.yaml`).

### Revisão 2026-10-12: auditoria entre planos

Auditoria independente dos planos 0002–0007; itens aplicados neste plano
(decisões já tomadas, sem mudança de escopo):

- **F1 — `__post_init__` em opções em camadas**: fato verificado no Python

  Assinaturas (`core/components.py`); `DetectorOptions.__post_init__` valida

### Correções e reconciliações do texto original

- **Dependências**: a task_0001 **já está commitada** (`ddbb153 feat:
  adicionar pipeline de distância RF-DETR+DA3`); a frase "ainda não
  commitado" estava desatualizada. Na máquina com GPU o `.git` sincronizado ainda
  não tem commits (`fatal: … does not have any commits yet`).
- **YAML esboçado**: `distance.type` vira `distance.distance_type` (mesmo
  nome do campo de `DistanceConfig`, sem camada de tradução); `render`
  ganha `cmap`, `crf`, `hud`, `font` (flags atuais sem lugar no esboço);
  `device` vira chave de topo; `camera.estimate` ganha `process_res`,
  `process_res_method` e `hf_cache` (a estimativa usa hoje os do modelo de
  profundidade, `cli.py:382-390`; explicitar evita acoplamento entre seções).
- **"Intrínsecos previstos por quadro (NESTED)" não é um
  `IntrinsicsProvider`**: é uma propriedade do adaptador de profundidade
  (`needs_intrinsics == False`), e o pipeline então não resolve
  intrínsecos — exatamente o que `cli.py:381` e `cli.py:420-421` fazem hoje.
  Provedores desta task: `FixedIntrinsics` e `EstimatedIntrinsics`.
- **Cronometragem fora do *template method***: o `__call__` da base faz
  filtro → rótulos → validação; o tempo é medido pelo `Pipeline` em volta de
  cada chamada (`_timed`), porque estágios que não são componentes
  (distância, render) precisam do mesmo mecanismo e o componente fica sem
  estado por chamada.
- **Máscaras**: o contrato `Instances.masks` (resolução do quadro) entra
  agora, mas consumi-las exige reamostrar para o mapa de profundidade, que é
  escopo explícito da task_0004 ("Reamostragem de máscara para o mapa").
  Nesta task o pipeline usa só caixas e nenhum adaptador preenche `masks`.
- **Filtro de classes do YOLO**: o script de referência passa `classes=ids`
  ao `predict()` e, no preset `driving`, ignora nomes ausentes
  (`infer_video.py:278-288`). Aqui o filtro é único, na base `Detector`,
  após o `_predict` (mesmo comportamento para todos os adaptadores) e
  estrito (nome desconhecido → erro de configuração), como na task_0001.

**Regra das opções em camadas (Revisão 2026-10-12, F1)** — vale para
`DetectorOptions` e toda base de opções `@dataclass(frozen=True,
slots=True, kw_only=True)` das tasks seguintes (`FusionOptions` 0003;
`RefinerOptions` → `BoxPromptOptions` → `HFSamOptions`/
`UltralyticsSamOptions` 0005; `TrackerOptions` 0006): o `__post_init__`
de uma classe filha chama o da base **explicitamente**,
`Base.__post_init__(self)` (ex. `DetectorOptions.__post_init__(self)`),
e **nunca** `super().__post_init__()` sem argumentos — com `slots=True` o
decorador recria a classe e a célula `__class__` do `super()` aponta para
a classe original, o que levanta `TypeError: super(type, obj): obj must
be an instance or subtype of type` (verificado no Python 3.11.13 do
projeto). Filha sem validação própria não declara `__post_init__` e herda
o da base (funciona). O caso é coberto por teste em `test_components.py`
(Passo 3).

```python
at frame resolution; depth stays at the model's native map resolution and
carries the frame -> map `MapGeometry` (resampling would cost time and blur
edges). Per-instance fields of `Instances` carry `per_instance(check)`
metadata - their own validator and optional concat fill - so
`select`/`concat`/`validate` handle fields added later (fused `sources`,
`track_id`, ...) without changes.

Import rule: this module never imports `distance` at run time (distance
imports MapGeometry/CameraIntrinsics from here); distance types used in
annotations are imported under TYPE_CHECKING only. It is contract-only:
it never imports `core.pipeline`, `config`, `camera`, `io` or adapters
(`core.pipeline` imports from those modules, never the reverse).
"""
```

### `CameraIntrinsics`
```python
"""Pinhole intrinsics in pixels, at frame or depth-map resolution (the
holder says which).

Continuous pixel coordinates: pixel i is centred at i + 0.5, so a centred
camera has its principal point at (W/2, H/2), consistent with box edges,
MapGeometry and ray_factors. OpenCV centres pixel i at i, so its cx/cy are
0.5 smaller; convert when reading or writing OpenCV matrices.
"""
```

### `Instances` / `Instances.validate` / `Instances.has_mask`
```python
"""Instances detected (or segmented) in one frame, possibly by several models.

`label` is the canonical name used downstream, `raw_label` the name in the
producing model's vocabulary, `source` the producing component's name.
`masks`, when present, are boolean (N, H, W) at frame resolution; an
all-False mask means "no mask" for that instance, which lets detectors with
and without masks be concatenated (missing masks are filled with False).
"""

"""Check shapes, dtypes and geometry against a frame of `frame_w` x `frame_h`
by running the validator declared in each per-instance field's metadata.

Raises:
    ContractError: an adapter returned malformed instances (a bug in the
        adapter, never a user configuration problem).
"""

"""(N,) bool: whether each instance has a usable mask, i.e. at least one
True pixel inside its box window (pixels whose centre lies in the box, the
rule of box_to_map_pixels). Mask pixels outside the box are ignored, as the
mask distance does."""
```

### Desvios do plano original

- **Sem `git mv`**: a sessão não executa operações git; os arquivos foram recriados nos novos caminhos e os antigos apagados (o git detectará os renomes no `add`).
- **`ultralytics-platform` 0.1.84** no lock (o plano citava 0.1.83 da resolução de 2026-10-12); continua 8 pacotes novos e nenhuma versão existente alterada.
- **`half` → `quantize=16`**: no ultralytics 8.4.175 instalado, `half` está depreciado (aviso "Use 'quantize' instead"; `cfg/__init__.py:613-622`). A opção do YAML continua `half`, mas o adaptador passa `quantize=16 if half else None`.
- **`YOLO_CONFIG_DIR` criado antes do import**: verificado na máquina com GPU que o ultralytics só cria `…/Ultralytics` se o diretório pai já existe (`get_user_config_dir`); senão cai para `/tmp/Ultralytics`. O `_load` faz `mkdir` do diretório antes do import.
- **`Pipeline.setup` dividido em `resolve_intrinsics` + `load`** (o `setup` continua existindo e chamando os dois): o CLI precisa chamar `DeviceMonitor.start()` entre eles para manter a semântica de `peak_vram`/`device_mem_used_delta` da 0001 (linha de base depois de liberar o modelo da focal, antes dos modelos principais).
- **`_timed(fn, *args)`** em vez de `_timed(fn: Callable[[], T])`: evita lambdas em laço.
- **`select`/`concat`/`validate` iteram os campos de `type(self)`/`type(parts[0])`** (não só de `Instances`): permite testar (e futuramente usar) campos novos declarados numa subclasse; `concat` devolve a classe da primeira parte.
- **`Detector.describe()` acrescenta `vocabulary`** na base (em vez de cada `_describe` do adaptador repeti-lo); `DA3Depth._describe` inclui `fixed_intrinsics`, lido pelo `MetricsSink` para `focal_map_intrinsics` (o sink não conhece o DA3).
- **`ProcessResMethod` (`Literal`)** criado em `adapters/depth/da3.py`, com `PROCESS_RES_METHODS = get_args(ProcessResMethod)`; usado por `DA3Depth.Options` e `EstimateConfig` para validar o método já na configuração.
- **`estimate_focal_frame_px`** passou a levantar `ConfigError` (subclasse de `ValueError`) com mensagens nas chaves novas (`camera.estimate.model`, `source.start/duration`), porque o `main` agora só captura `ConfigError`; o resto da função ficou inalterado.
- **`DA3Depth._load` checa a ausência de intrínsecos antes de carregar o modelo** (o plano a colocava após a carga) — falha mais barata, mesma mensagem.
- **`apply_overrides` cria mapas intermediários ausentes** (ex. `--set output.tag=x` num YAML sem seção `output`); o erro fica para índice de lista inválido/fora do intervalo e para caminho que desce num escalar. Chaves mal escritas continuam rejeitadas pelo `from_mapping`. Consequência documentada no teste: `--set aggregation.iou=0.5` num YAML sem `aggregation` cria um spec sem `type`.
- **`RenderConfig` valida `cmap`** (antes só o `Renderer` falhava, já depois de carregar os modelos).
- **`load_config` recusa `exclude_sky` no topo do YAML** (só é aceito dentro de `distance`), para não haver duas grafias.
- **`run()` constrói os componentes antes de sondar o vídeo** (`VideoSource` depois do `registry.build`), para que opções inválidas saiam com código 2 mesmo com um vídeo ilegível; `VideoSource` com vídeo ausente/inexistente → `ConfigError`.
- **`MetricsSink`/`NpzSink` não gravam nada quando nenhum quadro foi processado** (a 0001 também não gravava `metrics.json` nesse caso); o progresso a cada 100 quadros passou a mostrar o tempo decorrido em vez da p50 de profundidade.
