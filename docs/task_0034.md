# Task 0034: `ultralytics` (AGPL-3.0) as an opt-in `yolo` extra (COMPLETED)

## Description

The project is Apache-2.0, but the `infer` extra installs `ultralytics`
(AGPL-3.0) and, through it, `ultralytics-platform` (AGPL-3.0-only) and
`ultralytics-thop` (AGPL-3.0). Every GPU install therefore pulls AGPL code
whether or not a YOLO model is used, and the web interface (a network
service) would make section 13 of the AGPL apply to that combination. The
licence audit (2026-11-05) found no other copyleft dependency in the `infer`
stack (`rfdetr`, `depth-anything-3`, `transformers`, `timm`, `opencv-python`,
`av`, `fastapi`: Apache-2.0/BSD/MIT).

This task moves `ultralytics` out of `infer` into its own `yolo` extra, so
the default install carries no AGPL code and YOLO is an explicit opt-in. The
provisioning layer already supports per-model extras, so the two adapters
that import `ultralytics` (`yolo`, `ultralytics_sam`) declare `extra="yolo"`.
Closes the README roadmap item "ultralytics as an optional extra".

| File | Reason |
|------|--------|

| `LICENSE`, `license` in `pyproject.toml` | The project's own code stays Apache-2.0; it only imports `ultralytics` lazily |
| `configs/` | YAMLs do not name extras |

## Implementation details

- `yolo = ["ultralytics==8.4.175"]` added, removed from `infer`; `uv.lock` refreshed with
  `uv lock --offline` (only the extra marker and `provides-extras` changed).

- `run_web.sh` adds `--extra yolo` when `ultralytics` is in the target environment.
- `tests/test_adapter_requirements.py` expects `yolo` for adapters that list `ultralytics`;
  `tests/test_run_web_script.py` covers the script change.
- Not changed: `AGENTS.md`/`gpu_pending.sh` commands (`--extra infer`), which are for the
  RF-DETR/DA3 path; YOLO steps on the GPU host need `--extra yolo` added by hand.
- The `.venv-infer` environments on disk still hold `ultralytics`; they were not re-synced.
