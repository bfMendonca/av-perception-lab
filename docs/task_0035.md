# Task 0035: Render-only per-class selection for semantic segmentation

## Description

Turning on SegFormer paints all 19 Cityscapes classes over the video at
`render.semantic_alpha` (0.4), which buries the frame. Today the only render
controls are the global alpha and `render.semantic_overlay`, which picks whole
maps, not classes. This task adds `render.semantic_classes` (an allowlist of
`<map>.<class>` entries, `None` = every class) and lets the web editor choose
the classes from a list the interface knows before any model runs.

Selection is presentation only: hiding a class never changes distance,
tracking, CSV, NPZ or metrics. Existing YAMLs and runs render exactly as
before. Detector render filtering is out of scope this round; the class
declaration API is designed so it can follow without rework.

Design: `docs/superpowers/specs/2026-11-08-render-class-selection-design.md`.
Plan: `docs/superpowers/plans/2026-11-08-render-class-selection.md`.

## Planning

### Step 1: Config and name resolution
`render.semantic_classes`, prefix check at config load, class check at
`Pipeline.load` (`ConfigError` listing the valid names). Allowlist semantics.

### Step 2: Renderer, sink and CLI
Hidden classes alpha 0 in the lookup table (as `SEMANTIC_BACKGROUND`);
`(class_names, visible)` cache key; `VideoSink` passes the resolved set.

### Step 3: Class declaration
`ClassCatalog` and `Component.declared_classes(options)` (default `None`).
TwinLiteNet+ constant; SegFormer from `config.json` in the HF cache.

### Step 4: Load-time cache
After a successful `load()` write `<weights root>/.classes/<key>.json`; key from
resolved path, size and mtime; used as a hint by `declared_classes`.

### Step 5: Web endpoint
`POST /api/classes` builds the options dataclass and returns `{names, source}`
or `{names: null}`, with no model load or unpickling.

### Step 6: Editor dropdown
Checkbox dropdown (all checked, select all/none, search); writes the field only
when the selection is not "all"; `background` listed but disabled.

### Step 7: Docs and closing
DESCRIPTION, reference, CHANGELOG, web_extending; mark this task `(COMPLETED)`
with Implementation details and Test notebook.

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Hiding a class changes distance or outputs | Low | Only `Renderer` reads the set; tests assert CSV/NPZ/metrics unchanged |
| Wrong class list silently draws the wrong thing | Medium | Class names validated at `Pipeline.load` with `ConfigError`; contract test `declared_classes == class_names` after load |
| Stale cache after weights are replaced | Medium | Key includes path, size and mtime; cache is a hint, `class_names` after load is authoritative |
| Read-only weights root breaks the cache write | Low | Write failure is logged and ignored |
| Web request unpickles an arbitrary checkpoint | Low | The endpoint never loads a model; metadata and cache only |
| Allowlist hides classes of a model added later | Medium | Documented in the field comment and the reference |
| Stale lookup table in the renderer | Low | Visible set is part of the cache key |
