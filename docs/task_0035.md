# Task 0035: Render-only per-class selection for semantic segmentation (COMPLETED)

## Description

Turning on SegFormer paints all 19 Cityscapes classes over the video at
`render.semantic_alpha` (0.4), which buries the frame. Today the only render
controls are the global alpha and `render.semantic_overlay`, which picks whole
maps, not classes. This task adds `render.semantic_classes` (an allowlist of
`<map>.<class>` entries, `None` = every class) and lets the web editor choose
the classes from a list the interface knows before any model runs.

Selection is presentation only: hiding a class never changes distance,
tracking, CSV, NPZ or metrics. Existing YAMLs and runs render exactly as
before. Detector render filtering is out of scope this round; the class
declaration API is designed so it can follow without rework.

Design: `docs/superpowers/specs/2026-11-08-render-class-selection-design.md`.
Plan: `docs/superpowers/plans/2026-11-08-render-class-selection.md`.

## Planning

### Step 1: Config and name resolution
`render.semantic_classes`, prefix check at config load, class check at
`Pipeline.load` (`ConfigError` listing the valid names). Allowlist semantics.

### Step 2: Renderer, sink and CLI
Hidden classes alpha 0 in the lookup table (as `SEMANTIC_BACKGROUND`);
`(class_names, visible)` cache key; `VideoSink` passes the resolved set.

### Step 3: Class declaration
`ClassCatalog` and `Component.declared_classes(options)` (default `None`).
TwinLiteNet+ constant; SegFormer from `config.json` in the HF cache.

### Step 4: Load-time cache
After a successful `load()` write `<weights root>/.classes/<key>.json`; key from
resolved path, size and mtime; used as a hint by `declared_classes`.

### Step 5: Web endpoint
`POST /api/classes` builds the options dataclass and returns `{names, source}`
or `{names: null}`, with no model load or unpickling.

### Step 6: Editor dropdown
Checkbox dropdown (all checked, select all/none, search); writes the field only
when the selection is not "all"; `background` listed but disabled.

### Step 7: Docs and closing
DESCRIPTION, reference, CHANGELOG, web_extending; mark this task `(COMPLETED)`
with Implementation details and Test notebook.

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Hiding a class changes distance or outputs | Low | Only `Renderer` reads the set; tests assert CSV/NPZ/metrics unchanged |
| Wrong class list silently draws the wrong thing | Medium | Class names validated at `Pipeline.load` with `ConfigError`; contract test `declared_classes == class_names` after load |
| Stale cache after weights are replaced | Medium | Key includes path, size and mtime; cache is a hint, `class_names` after load is authoritative |
| Read-only weights root breaks the cache write | Low | Write failure is logged and ignored |
| Web request unpickles an arbitrary checkpoint | Low | The endpoint never loads a model; metadata and cache only |
| Allowlist hides classes of a model added later | Medium | Documented in the field comment and the reference |
| Stale lookup table in the renderer | Low | Visible set is part of the cache key |

## Implementation details

What was done:

- `render.semantic_classes` (`RenderConfig`): `<map>.<class>` allowlist; `None` = all, `()` = none,
  a map without an entry draws none, a bare string becomes a one-item tuple. The map prefix is
  checked in `RunConfig.__post_init__`; `core.labels.resolve_semantic_classes` checks the classes
  after `pipeline.load` in `cli.run` (before frame 1). `background` is never drawn. The renderer
  gives hidden classes alpha 0 in the lookup table; the visible set is part of its cache key and
  `VideoSink` passes it. CSV, NPZ, metrics, distance and tracking are untouched.
- `ClassCatalog` and `Component.declared_classes(options)` (default `None`): TwinLiteNet+ static
  (`_check_heads` verifies two 2-channel heads at load), SegFormer `id2label` from `config.json`
  (HF cache or a local directory, plain JSON), detectors from `core/class_cache.py`
  (`<weights root>/.classes/<key>.json`, key = resolved path + size + mtime, written after every
  successful `Detector` load, write failures ignored, a hint only). `Detector.weights_file` is
  implemented by the YOLO and RF-DETR adapters.
- `POST /api/classes` (`web/classes.py`): `{kind, spec}` -> `{names, source}` or
  `{names: null, source: null}`; 422 `{errors}` for an unparsable spec, path checks or a local
  SegFormer `model` directory outside the weights root and asset roots. Options are parsed first,
  then paths are checked, then the declaration is asked; no model is loaded or constructed.
- Editor: `ClassSelect` (checkbox dropdown, search, select all/none, `background` listed but
  disabled) on `render.semantic_classes`, matched by field name. The config reaches field controls
  through `StageContext` under `CONFIG_CONTEXT_KEY`. Answers are cached by the serialized spec and
  new specs are debounced. A class list is cached for the page's lifetime, an "unknown" answer is
  not: it is asked again once per panel open (e.g. after "Prepare model"), never on edits or keystrokes.
  SegFormer's declaration follows `refs/main` like the loader (sorted scan only as a fallback).
  An entry without `.<class>` is rejected at config load. Per-class editing is locked while a map's classes are unknown or
  loading and the value is "all", because the server only takes an allowlist and unchecking one
  class would silently leave that map out. "Select all" removes the key.
- `tests/web/test_extensibility.py` allows the `semantic` literal in `ClassSelect.tsx` (the control is tied to that section).
- Docs: `DESCRIPTION.md`, `docs/reference.md` (section "Render class selection"),
  `docs/web_extending.md` (one paragraph in section (f) on the `config` context key, which this task added to `StageContext`), `CHANGELOG.md`.

Deviations from the plan: the dropdown is in the Render panel only, not in each semantic stage
card (see below); `POST /api/classes` lives in `web/classes.py` (not `schema.py`) and
`security.found_path_problems` was split out of `path_problems` to reuse the path checks; the
lock on per-class editing was added after review.

### Known limitations / deferred

- The dropdown is only in the Render panel; the spec text also mentions each semantic stage
  (deferred).
- Detector render filtering and MCAP output remain follow-ups.
- Per-class editing is locked while a map's classes are unknown or loading.
- The reset button writes `null` (equivalent to the field being absent).
- Not tried in a real browser: the web UI was only tested with vitest.

### Security note

Pre-existing, found during review and not changed by this task: `/api/validate`,
`/api/models/status` and `/api/models/prepare` (through `schema.validate_config`) build components
before checking paths, so a client-supplied detector `labels` path is read by `LabelMap.load` and
its error text can reveal file content or existence. It needs its own task.
