# Task 0028: Google Drive download source and automatic TwinLiteNet+ weights

## Description

The TwinLiteNet+ pretrained weights (`pretrained/<variant>.pth`, variants
nano/small/medium/large) are only published on the upstream Google Drive
folder (README of `chequanghuy/TwinLiteNetPlus`, "Pre-trained Model"). Until
now they were declared `UserProvided`: Prepare (CLI `--prepare` and the web
"Prepare model") cloned the code and then asked the user to download the
file by hand. The user decided (2026-11-01) that Prepare downloads them.

This task adds a Google Drive source kind (`GoogleDriveAsset` +
`GoogleDriveSource`) built on the same streaming machinery as the URL source
(atomic `.part` + rename, Range/If-Range resume, size and sha256 checks,
redirect policy, cancel, size cap, free-disk check) and declares the four
TwinLiteNet+ files with their Drive file id, size and sha256.

## Planning

### Step 1: Research (network only for this)

Read the Drive folder listing (`embeddedfolderview`) for the four file ids,
download each file once into a scratch folder outside the repo, record
`Content-Length` and sha256, compare with the author's local copies.

### Step 2: Asset kind

`GoogleDriveAsset` with `UrlAsset`'s `present` (shared function), id
validated with `[A-Za-z0-9_-]{10,}`.

### Step 3: Source

Refactor the URL streaming into a base class parameterised by URL, opener
and a response check; `UrlSource` keeps its behaviour and tests.
`GoogleDriveSource` fetches
`https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t`,
redirects only within `drive.usercontent.google.com`, `drive.google.com`,
`*.googleusercontent.com` (https), refuses `text/html` answers and bodies
that start like HTML.

### Step 4: Engine order

Assets under a declared clone's folder wait for that clone to be ready.

### Step 5: TwinLiteNet+ declarations, tests, docs

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Drive serves an interstitial or quota page instead of the file | Medium | Detected (content type / HTML body), the `.part` is removed, a readable error names the manual download folder |
| Drive file replaced upstream | Low | size and sha256 pinned: a different file fails the check and is never accepted |
| Weights folder created before the clone blocks `git clone` | Medium | Engine skips assets inside a not-ready declared clone |
| A user's fine-tuned `<variant>.pth` at the default path | Low | `present` reports it invalid and nothing downloads over it (same rule as release names) |
| Regression of the URL source | Low | Shared code refactored, existing URL tests unchanged and green |
