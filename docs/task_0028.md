# Task 0028: Google Drive download source and automatic TwinLiteNet+ weights (COMPLETED)

## Description

The TwinLiteNet+ pretrained weights (`pretrained/<variant>.pth`, variants
nano/small/medium/large) are only published on the upstream Google Drive
folder (README of `chequanghuy/TwinLiteNetPlus`, "Pre-trained Model"). Until
now they were declared `UserProvided`: Prepare (CLI `--prepare` and the web
"Prepare model") cloned the code and then asked the user to download the
file by hand. The user decided (2026-11-01) that Prepare downloads them.

This task adds a Google Drive source kind (`GoogleDriveAsset` +
`GoogleDriveSource`) built on the same streaming machinery as the URL source
(atomic `.part` + rename, Range/If-Range resume, size and sha256 checks,
redirect policy, cancel, size cap, free-disk check) and declares the four
TwinLiteNet+ files with their Drive file id, size and sha256.

## Impact Analysis

| Drive serves an interstitial or quota page instead of the file | Medium | Detected (content type / HTML body), the `.part` is removed, a readable error names the manual download folder |

## Implementation details

- **Kind.** `GoogleDriveAsset(file_id, sha256, manual)` registered as
  `gdrive` in `core/requirements.py`. `present` is the URL kind's, now one
  shared function (`_single_file_state`): an existing file of another size or
  sha256 is "invalid" (never downloaded over), a `.part` alone is "partial".
  `file_id` must match `[A-Za-z0-9_-]{10,}` (`UnsafePathError` otherwise);
  `describe_source()` is "Google Drive file <id>"; `manual` is the page shown
  when Drive refuses (the upstream folder).
- **Source.** The URL source's streaming code became the base class
  `_HttpFileSource` (`_url`, `_where`, `_opener`, `_reason`,
  `_check_response`, `_check_first_chunk` hooks); `UrlSource` only supplies
  `_url` (scheme check) and its messages are unchanged (the existing URL
  tests pass untouched). `_http_reason` takes the name to show instead of the
  asset. `_open(request, opener=None)` is still the single network entry
  point that tests replace. `GoogleDriveSource` builds
  `https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t`,
  follows redirects with `_DriveRedirect` (https only; hosts
  `drive.usercontent.google.com`, `drive.google.com`, suffix
  `.googleusercontent.com`; the refusal names the host, never the URL, as a
  Drive redirect may carry a signed query), refuses a `text/html` /
  `application/xhtml` content type before writing and a first chunk that
  starts like HTML (the `.part` and `.part.meta` are removed). HTTP 403/429
  add "Drive quota or access limit: try again later or download it manually
  from <manual>". `endpoint`, `hosts`, `host_suffixes`, `schemes` are class
  attributes so tests point it at a local server.
- **Endpoint behaviour (verified 2026-11-01).** For the four public files the
  endpoint answers `200 application/octet-stream` directly (no redirect, no
  interstitial), with `Content-Length`, `Last-Modified` (no ETag) and
  `Accept-Ranges: bytes`; a `Range: bytes=100000-200000` with
  `If-Range: <Last-Modified>` answers `206` with the right bytes, so resume
  works with the saved validator. No deviation from the planned endpoint.
- **Engine order.** Code repos already ran before assets; added
  `_unready_clone_around`: an asset whose target is inside a declared code
  repo's folder is skipped ("not downloaded: it goes inside code:<name>,
  which is not ready (the clone comes first)") while that repo is not ready.
  Chosen over declaring the weights outside the clone because it keeps the
  documented default (`<repo>/pretrained/<variant>.pth`, where users already
  placed the file by hand and where an explicit `repo:` clone keeps its
  weights), and it fixes the actual hazard: a failed clone followed by a
  download would create `_code/TwinLiteNetPlus/`, and the next clone would
  refuse "exists but is not a git clone".
- **TwinLiteNet+.** `TWINLITENET_WEIGHTS` (variant -> id, bytes, sha256),
  `DRIVE_FOLDER`, `WEIGHTS_LICENSE = "MIT"`, `canonical_weights_target()`.
  `<variant>.pth` inside the weights root is a `GoogleDriveAsset`; `known`
  only when `repo` is the default and the target is
  `_code/TwinLiteNetPlus/pretrained/<variant>.pth` (an explicit `repo`, even
  the same folder, or a `weights` elsewhere in the root is CLI-only). Any
  other file name in the root stays `UserProvided`; paths outside the root
  are not declared (unchanged). The load-time hint names `--prepare` and the
  Drive folder.
- **Licence.** `LICENSE` of the clone (and of `~/dev/TwinLiteNetPlus`): MIT,
  "Copyright (c) 2025 Chế Quang Huy". The Drive folder and files carry no
  licence of their own; the repository's licence is assumed for the weights
  (recorded as `license="MIT"`). This is an assumption, not a statement by
  the author: the models were trained on BDD100K, whose own licence terms
  apply to the data.
- **Web.** No change: the rows are generic, a known downloadable asset is
  preparable, so TwinLiteNet+ rows no longer get `reason: "user_provided"`.
