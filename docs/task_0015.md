# Task 0015: Front-end da interface web e editor visual de pipeline (CONCLUÍDA)

## Descrição

Terceira de cinco entregas da interface web (design em
`docs/superpowers/specs/2026-10-31-web-interface-design.md`, plano em
`docs/superpowers/plans/2026-10-31-web-interface.md`). As tasks 0013 e 0014
entregaram o backend (catálogo, validação, fila e histórico); esta cria o
front-end em `web/` (React + TypeScript + Vite, tema escuro, interface em
inglês) com o editor visual da pipeline:

- pistas de estágios lidas do catálogo (`GET /api/catalog`), um cartão por
  módulo, "+ add" nos estágios de várias vagas;
- inspetor à direita com os campos gerados do esquema das opções (slider,
  select, switch, texto/caminho, lista, grupo aninhado, "Advanced" recolhido)
  e um painel "General settings" para as seções gerais;
- abrir e salvar YAML (parse/dump do servidor), chaves desconhecidas mantidas
  como `extras`, aviso único de perda de comentários;
- validação no servidor com debounce de 400 ms e erros presos ao campo pelo
  caminho pontilhado; diff do YAML sob o inspetor.

Requisito central (usuário): à prova de futuro. Nenhum nome de estágio,
modelo ou campo fica no front-end; estágio, tipo de campo e artefato
desconhecidos caem em alternativas genéricas (pista genérica, editor YAML
bruto com validação) e há um registro de extensões (`registerStageView`,
`registerFieldControl`). O botão Process fica desabilitado (a Task 0016 o
liga). O FastAPI passa a servir `web/dist` em `/` com fallback de SPA quando
o build existe.

## Planejamento

### Passo 1: Ambiente

Instalar o node LTS sem sudo (tarball oficial em `~/.local/share/node`,
`PATH` no comando, sem editar arquivos de shell) e documentar no `README.md`.
Criar `web/` com Vite React TS, vitest + Testing Library + jsdom, tokens do
tema escuro como variáveis CSS (sem tema claro, sem i18n).

### Passo 2: Testes (falham)

Os 12 testes do plano: pista genérica para estágio desconhecido; editor YAML
bruto para tipo de campo desconhecido; `registerFieldControl` sobrepõe o
controle padrão; `catalog_version` maior que o suportado mostra aviso e
renderiza; slider para float com faixa; select para enum; "Advanced"
recolhido; `addModule` com padrões do esquema marca `dirty`; `removeModule`
em estágio de vaga única recusado; `setOption` aninhado e `diff()`; `load`
mantém `extras` e `toConfig` os reemite; erros do servidor presos ao campo.

### Passo 3: Implementação

Estado puro (funções testáveis) + hook `useEditor` (`useSyncExternalStore`).
Pistas na ordem do catálogo (`general = false`); estágio com `kind` =
cartões de especificações `{type, name?, ...}`, estágio com seção = um cartão
da seção. Inspetor segue o clique; engrenagem "General settings" abre as
seções `general = true`. Diff contra o último YAML aberto/salvo.

### Passo 4: Servir o build

`create_app` monta `web/dist` (quando existe) em `/`: arquivos estáticos e,
para qualquer outro caminho fora de `/api`, o `index.html`.

### Passo 5: Verificação

`npm test`, `npm run build`, suíte Python da web, servidor real com o build e
o YAML recomendado.

## Detalhes de Implementação

### O que foi feito

- **Node** v24.22.2 (LTS) do tarball oficial, conferido por SHA-256, em
  `~/.local/share/node/node-v24.22.2-linux-x64` com o link
  `~/.local/share/node/current`; nada de sudo nem de arquivos de shell
  (comandos no `README.md`).
- **`web/`**: Vite 8 + React 18.3.1 + TypeScript 5.9, versões exatas no
  `package.json` e `package-lock.json`; `yaml` 2 para o editor YAML bruto;
  vitest 5 + Testing Library + jsdom. `npm run build` = `tsc -b && vite build`.
- `src/api/{types,client}.ts`: tipos do catálogo e de `Field` espelhando
  `web/schema.py` (tipos de campo abertos: `KnownFieldType | string`) e um
  cliente injetável (`ApiClient`) das rotas `catalog`, `validate`, `parse`,
  `dump`.
- `src/editor/paths.ts` (caminhos ↔ forma pontilhada do servidor, `setIn`
  imutável, `diffTrees`), `catalog.ts` (pistas, padrões do esquema, resumo dos
  cartões, `refineErrors`), `registry.ts` (`registerStageView`,
  `registerFieldControl`; o registro mais recente vence e cada chamada
  devolve o desfazer).
- `src/editor/yamlState.ts`: `createEditorStore(client)` + `useEditor()`
  (`useSyncExternalStore`) com `addModule`, `removeModule`, `disableStage`,
  `changeType`, `setOption`, `setExtra`, `load`, `loadParsed`, `restore`,
  `toConfig` (config + extras), `diff`, `markSaved`, `dirty`, seleção e
  validação com debounce de 400 ms (respostas atrasadas descartadas por
  sequência).
- `Lanes`, `ModuleCard`, `Inspector`, `fieldControls`, `DiffView`,
  `EditorView`, `ui/Shell`, `ui/Dialog`, `ui/icons`, `ui/theme.css` (tokens
  do tema escuro em `:root`), `App.tsx` (catálogo com estados de carga e
  erro, abrir/salvar, aviso de versão, notificações, arrastar arquivo,
  rascunho em `localStorage`).
- `web/app.py`: `create_app(..., static_dir=DEFAULT_STATIC_DIR)` com uma rota
  final `GET /{rel:path}` que serve arquivos de `web/dist` via `safe_join` e
  cai no `index.html`; `api`/`api/*` sempre 404; o `index.html` é procurado
  por requisição (um build feito com o servidor no ar passa a valer).

### Desvios do plano original

- Pistas (rodada de correção 1, decisão do controlador): `Stage` ganhou
  `group: str | None = None` (aditivo), exposto no catálogo; o front-end
  junta estágios consecutivos com o mesmo grupo numa pista com o título do
  grupo, sem nomes fixos. `tracking` e `smoothing` têm
  `group="Tracking & filter"` e `semantic` passou de `order=45` para 75, o
  que dá a ordem do plano: Source → Detectors → Aggregation → Refiners →
  Depth → Tracking & filter → Semantic → Motion. A ordem do registro não
  afeta a execução (`Pipeline` não a lê).
- `fieldControls(field, ctx)` recebe também valor, `onChange`, caminho e
  erros (a assinatura `fieldControls(field)` do plano não teria como ligar o
  controle ao estado).
- `removeModule` em estágio de vaga única é recusado; para desligar um
  estágio opcional de vaga única há `disableStage` (a chave sai do YAML).
- Erros de domínio levantados no `__post_init__` das opções voltam do
  servidor no caminho da especificação (`detectors[0]: threshold must be in
  (0, 1], got 7.0`); o front-end prende ao campo quando a mensagem começa com
  o nome de um campo do esquema (`refineErrors`), sem nomes fixos.
- Testes além dos 12 do plano: `catalog.test.ts` (6) e
  `tests/web/test_static.py` (5).
- Rodada de correção 1 (revisão `task-3-review.md`): teste de
  `registerStageView` (`Lanes.test.tsx`); corrida da validação corrigida
  (`validationSeq` também sobe em `scheduleValidation`, então a resposta de
  uma requisição em voo fica obsoleta após uma edição; teste em
  `yamlState.test.ts`); `--static-dir` no `server.py`; o fallback de SPA dá
  404 para arquivo ausente em `assets/` ou com extensão, e `/api/*`
  desconhecido segue 404 JSON (`test_static.py`).
- Verificação manual pela rede local (`--host 0.0.0.0`) não foi feita: o
  ambiente do agente bloqueou expor o serviço; a mesma sequência foi feita em
  `127.0.0.1` com Chrome headless.

### Observações

- `validate` recebe `toConfig()` com os `extras`: a CLI recusa chave de topo
  desconhecida, então a interface também mostra o erro (e o
  `config_from_mapping` para no primeiro erro de forma, escondendo os
  seguintes enquanto o extra existir).
- O Process continua desabilitado; a `task_0016` estende `Shell.tsx` e usa
  `useEditor().toConfig()`.
- O aviso de salvar é guardado em `localStorage` (`ddd.editor.saveWarningSeen`);
  sem storage, vale por sessão.
