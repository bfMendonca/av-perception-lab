# Task 0033: MCAP (ROS 2) input (COMPLETED)

## Description

Today a run starts from a video file. Recordings from simulators and robots
are MCAP files (ROS 2). This task lets the pipeline read an image topic
(`sensor_msgs/Image` or `CompressedImage`, CDR) straight from an `.mcap`,
using the message timestamps as `Frame.t` and the topic's `CameraInfo` as a
calibration source, optionally rectifying the images. The web interface
accepts an `.mcap` drop or import, lists its image topics and lets the user
choose one. Video runs keep working unchanged.

Design: `docs/superpowers/specs/2026-11-04-mcap-input-design.md`.
Plan: `docs/superpowers/plans/2026-11-04-mcap-input.md`.

## Implementation details

### Reader (`io/mcap_reader.py`)

- `probe_mcap(path)` returns the image topics (`sensor_msgs/msg/Image`,
  `CompressedImage`), their `CameraInfo` topics, counts, rates and durations.
  Counts and first/last times come from the summary when the file is indexed;
  an unindexed file is scanned once. Every failure is wrapped in `McapError`
  (truncated or corrupt files included). The `mcap` libraries are imported
  lazily, inside functions.
- Each image topic is paired with the `CameraInfo` topic that shares the
  longest namespace prefix (root-level topics pair together; no shared
  component means no pair).
- Raw encodings: `rgb8`, `bgr8`, `rgba8`, `bgra8`, `mono8`; compressed:
  `jpeg`/`png` (detected by substring, so `"rgb8; jpeg compressed bgr8"` works).
  `ImageTopic.supported` / `unsupported_reason` mark other topics (16UC1,
  compressedDepth, ...): they are listed but cannot be selected.
- `iter_images` decodes with the row `step` honoured; `read_camera_info`
  returns a `CameraInfoMsg`.

### McapSource and FrameSource

- `FrameSource` gains `input_name`, `nominal_fps`, `n_frames_total`,
  `with_transform` (abstract) and `audio_from()`, `camera_info()`,
  `frame_times_known` (defaults). `VideoSource` keeps its public API.
- `McapSource` (constructor probes the file; `McapError`, missing topic or
  file become `ConfigError`). Time base: `header.stamp` when every stamp of
  the first 50 messages is > 0 and non-decreasing, otherwise the log time.
  Messages whose time is not greater than the last kept one are dropped and
  counted in `describe()["duplicates_dropped"]`. `Frame.t` is in seconds from
  the first selected message; `start`/`duration` select by time, `stride`
  counts messages, `max_frames` caps the kept ones. A size change mid-topic
  raises `ContractError`. `describe()` is stored in `metrics.json["video"]`
  (key `time_base`); there is no `metrics["source"]`.

### CameraInfo intrinsics

- `camera.calibration_from_camera_info`: a raw message uses K and D (plumb_bob
  or rational_polynomial), a rectified one (D empty or zero) the left 3x3 of
  P; equidistant, non-zero ROI, binning > 1, a bad D length or a size
  mismatch are refused (`ConfigError`). `cx`/`cy` gain 0.5 as for files.
- `build_camera(cfg, source, rectify)` has one code path for file, CameraInfo
  and rectified intrinsics. Precedence: `rectify.enabled` > `from_source` >
  `calibration.path`. `focal_estimate_config` returns `None` when rectify
  supplies K, so the DA3 focal model is not demanded.

### Config keys

- `source.mcap` and `source.topic` (exclusive with `source.video`; a topic is
  required). `camera.calibration.from_source` (exclusive with `path` and with
  `undistort`; `path` is now optional). New `rectify` section
  (`enabled`, `alpha`) and a `rectify` stage (order 15, optional).
  `RunConfig` refuses `from_source`/`rectify.enabled` without `source.mcap`,
  and `rectify.enabled` with `camera.focal_px` or `calibration.path`.

### Rectify stage

- With `rectify.enabled`, frames pass through an `Undistorter` (K and D from
  the CameraInfo, `alpha` as in `calibration.undistort`) before every
  component; the K handed to depth is the rectified one. It needs a topic with
  a CameraInfo that has distortion; otherwise `ConfigError` before any model
  loads. `metrics.json` records the raw K/D (`camera.calibration`) and the
  `undistort` block, so evaluation transforms references as for a file.
  If a calibration file is also set in the YAML, the CameraInfo wins, a
  warning is printed and `details["ignored_calibration"]` records the path.

### Variable-frame-rate video

- `io.video.TimestampedVideoWriter` (PyAV, libx264, 1/90000 time base,
  `+faststart`) writes each frame at its real `t`; PTS read back match the
  input. It refuses odd sizes, non-finite or non-increasing `t`. `VideoSink`
  uses it when `source.frame_times_known` (no audio is copied); the
  constant-fps `VideoWriter` path is unchanged for videos.

### Evaluation

- `evaluation/run_data.load_run` accepts `video.fps` or `video.nominal_fps`;
  `RunData.fps` / `has_frame_times` added; for MCAP runs `frame_times` use
  the CSV `t`. An MCAP run with `source.start > 0` is refused
  (`ConfigError`): `Frame.t` of an MCAP counts from the first selected
  message, while a video's `t` includes `start`, so references would be offset.

### Web backend

- `.mcap` uploads and imports become `kind: "mcap"` library records (old
  records load as `video`), validated with `probe_mcap`, thumbnail = first
  frame of the first supported topic, no preview.
- `GET /api/videos/{id}/topics` returns the stored summary (also in
  `record.mcap`). `POST /api/runs` with an MCAP `video_id` binds
  `source.mcap`, requires a supported `source.topic` and refuses (422)
  `rectify.enabled` / `from_source` on a topic without a usable CameraInfo.
  `source.mcap` is in `SERVER_CHECKED_PATHS`; `rerun`, `reopen` and job titles
  handle MCAP runs.

### Web frontend

- Drop zone, picker and library accept `.mcap`; `TopicPicker` (topics with
  badges, unsupported ones disabled with the reason) and a "Use the CameraInfo
  for the intrinsics" tick; `RectifyLane` (a stage view registered with
  `hidden`, shown only for an MCAP input) with the pure availability rules in
  `mcapCamera.ts`; `useMcapBinding` keeps `source.mcap`/`source.topic` in
  sync with the selected input; the deck shows the thumbnail instead of a
  player. The editor registry gained `StageContext` and `hidden`.

### Deviations from the plan

- The source description is `metrics.json["video"]`, not a new `source` key.
- The evaluation needed a fix (found by the smoke test): MCAP runs have no
  `video.fps`.
- `describe()` of an MCAP carries `nominal_fps`, not `fps`.
