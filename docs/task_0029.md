# Task 0029: One command to start the web interface (`utils/run_web.sh`) (COMPLETED)

## Description

Starting the web interface today takes three commands and a tool most users do
not otherwise need: build the front-end with Node (`npm ci`, `npm run build`),
install the right extras (`uv sync --extra web`, or `--extra infer --extra web`
with a GPU), then start the server with the same extras. Forgetting the build
gives `{"detail":"front-end not built (cd web && npm run build)"}`, and running
`uv run --extra web` in an environment that already has the GPU stack removes
that stack (the sync is exact).

`utils/run_web.sh` does it in one command from a fresh clone: it checks the
prerequisites, builds the front-end when `web/dist` is missing, picks the extras
so an installed GPU stack is never removed, and starts `det-depth-distance-web`.

## Planning

### Step 1: Script

Run from the repository root whatever the caller's directory. Checks `uv`
(always) and Node 22.12+ with npm (only when the front-end must be built), with
a message that names what is missing and where to get it. Builds with
`npm ci` and `npm run build` when `web/dist/index.html` is missing, or with
`--rebuild`. Extras: if the target environment (`UV_PROJECT_ENVIRONMENT`, else
`.venv`) already holds PyTorch, or `--gpu` is given, use `--extra infer --extra
web`; otherwise `--extra web`. Never choose fewer extras than what is installed.
Then `exec uv run <extras> det-depth-distance-web "$@"` and print the URL
before it starts. `--dry-run` prints the commands and runs none of them.

### Step 2: Tests

Syntax check, `--help`, and `--dry-run` outputs for each branch of the logic,
using a temporary environment directory with and without a fake PyTorch folder.

### Step 3: Documentation

README quick start, AGENTS.md, DESCRIPTION.md, CHANGELOG.md.

## Impact Analysis

- No runtime code changes; the script is new and optional.
- The only way to lose data is the `uv` sync removing packages, which the extras
  rule prevents (it never selects fewer extras than the installed ones).
- `--gpu` on a machine without a GPU installs about 9 GB; the script prints that
  before running `uv`.

## Dependencies

None.

## Implementation details

- `utils/run_web.sh`: `uv` is always required; Node.js 22.12+ and npm only when
  `web/dist/index.html` is missing or `--rebuild` is given. The target
  environment is `UV_PROJECT_ENVIRONMENT` or `.venv`; if it already holds a
  `torch` package (or `--gpu` is given) the extras are `infer` + `web`, otherwise
  `web`. The script ends with `exec uv run <extras> det-depth-distance-web
  <other arguments>`; `--host` and `--port` are read only to print the URL.
  `--dry-run` prints each command with a leading `+` and runs none.
- `tests/test_run_web_script.py` (15 tests): the script is copied into a fake
  checkout with fake `uv`, `node` and `npm` on a controlled `PATH`, so no real
  tool, download or server is involved.
- README quick start steps 2 and 3 use the script; the manual commands are
  listed after the steps. CHANGELOG, DESCRIPTION and AGENTS updated.

Real runs:

- Brand-new `git clone` (no `.venv`, no `web/dist`), `utils/run_web.sh --port 8021`
  with Node 24.22.2: built the front-end (`npm ci`, `npm run build`), installed
  the `web` extra, started the server; `GET /` and `GET /api/catalog` answered 200.
- The real repository with the GPU environment (`UV_PROJECT_ENVIRONMENT=_testbed/venv-infer`),
  `utils/run_web.sh --port 8022`: kept the GPU stack (the environment stayed at 9.0 GB)
  and the status of `configs/rfdetr_da3.yaml` read `ready` for every model.

Not run: `utils/run_web.sh --gpu` on a machine without the GPU stack (it would
install about 9 GB); the branches of the script it takes are covered by the
dry-run tests.
