# Task 0021: Adapter requirements and portable sample YAMLs (COMPLETED)

## Description

`task_0019` added the requirements declaration and the torch-free status
check, `task_0020` the provisioning engine and `--prepare`. No adapter
declares anything yet, so `--prepare` reports every model ready and a fresh
clone still fails on paths of the author's machine. This task migrates every
adapter (spec `docs/superpowers/specs/2026-10-31-model-readiness-design.md`,
"Migration"):

- every registered adapter implements `requirements(options)`, computed from
  the validated options only (never from `load()`), without importing torch;
- DA3 and the Hugging Face adapters (`sam2`, `edgetam`, `sam3_tracker`, `sam`,
  `sam_hq`, `segformer`) declare `HuggingFaceAsset`s in the `weights/hf` cache
  layout (an existing cache keeps working; nothing is moved); `hf_cache: null`
  now means `<weights root>/hf` instead of the user-wide HF cache;
- DA3 no longer downloads at run time: a missing checkpoint raises a
  `ConfigError` that names `--prepare` (also for the focal model of
  `camera.estimate`, which `--prepare` now prepares as well);
- RF-DETR declares a `UrlAsset` for the variant's checkpoint under
  `weights/rfdetr/` and loads it from that explicit path (existing
  `~/.roboflow/models` files are not touched and no longer read by default);
- YOLO and Ultralytics SAM declare a `UrlAsset` for the names published in the
  `ultralytics/assets` v8.4.0 release and `UserProvided` for any other file;
- TwinLiteNet+ declares the pinned clone (`CodeRepo`) under
  `weights/_code/TwinLiteNetPlus` and its pretrained file as `UserProvided`
  (see "Sources" below: the upstream weights are not in the git clone);
- `packages` = the import names, `extra="infer"`;
- every shipped `configs/*.yaml` drops machine paths (`~/dev/...`).

### Path convention (YAML overrides)

| Option | Default | Explicit value |
|---|---|---|
| `hf_cache` (DA3, `camera.estimate`, HF refiners, SegFormer) | `<weights root>/hf` | as before: relative to the working directory (repo root), `~` expanded |
| RF-DETR (no `weights`) | `<weights root>/rfdetr/<canonical file name>` | `weights:` a fine-tuned checkpoint, as before (`rfdetr.from_checkpoint`) |
| YOLO / Ultralytics SAM `weights` | (required) | a **bare file name** (no directory part, e.g. `yolo26l.pt`) resolves under `<weights root>/ultralytics/`; a path with a directory part keeps its old meaning (absolute, `~`, or relative to the working directory) |
| TwinLiteNet+ `repo` | `<weights root>/_code/TwinLiteNetPlus` | any clone, e.g. `~/dev/TwinLiteNetPlus` (as before) |

An explicit location **inside** the weights root is declared (and prepared)
like a default; a location **outside** it is the user's responsibility: it is
not declared as an asset (asset targets may never leave the weights root, see
`core.requirements.contained`), and `load()` fails with a clear `ConfigError`
if it is missing.

## Implementation details

- **Helpers.** `adapters/_weights.py`: `under_root(path)` (resolved, symlinks
  followed; None outside the root or for the root itself), `not_prepared()`
  (the `ConfigError` naming `--prepare`), `INFER_EXTRA`. `adapters/_hf_hub.py`:
  `default_cache()` / `resolve_cache()`, `is_repo_id()` (local directories are
  not declared), `hf_asset()` (weights file + `*.json`, sizes/licences from
  `HF_FACTS`), and `from_pretrained_offline` reading `<root>/hf` by default with
  a message naming `--prepare`. `adapters/_ultralytics.py`: the release table
  `ULTRALYTICS_ASSETS`, `check_weights` (refuses `.`/`..`/empty as a file name),
  `resolve_weights` (bare file name -> `<root>/ultralytics/`, any other path
  unchanged), `weights_asset`.
- **DA3.** `da3_requirements(model, hf_cache)` (also used for the focal model);
  `_load_da3` probes the cache with `HuggingFaceAsset.present` before importing
  `depth_anything_3` and loads with `local_files_only=True`; a
  `FileNotFoundError` from the hub (a file the probe missed) also becomes a
  `ConfigError`. A cache the probe cannot inspect (e.g. a symlinked cache that
  resolves elsewhere) skips the probe: `local_files_only` still never downloads.
- **RF-DETR.** `RFDETR_CHECKPOINTS` (variant -> library file name, URL, size);
  `_load` checks `checkpoint_path(variant)` before the import and passes
  `pretrain_weights=<path>` to the variant class (same class and defaults as
  before, so results are unchanged; the library's MD5 check still finds the
  file by its basename). The constructor was preferred over
  `rfdetr.from_checkpoint` for the COCO checkpoints: `from_checkpoint` infers
  the class from the checkpoint (or its file name) and is the fine-tuning path;
  it stays the path of an explicit `weights` file. An explicit missing
  `weights` file is now a `ConfigError` instead of the library's
  `FileNotFoundError`.
- **YOLO / Ultralytics SAM.** Known names -> `UrlAsset` (AGPL-3.0 / Apache-2.0),
  others -> `UserProvided`; `sam_h.pt` is not in the v8.4.0 release (HTTP 404)
  and is user-provided. The old curl hint of `ultralytics_sam` stays for paths
  outside the root.
- **HF refiners / SegFormer.** `requirements` on `HFSamRefiner` (all five
  families; EdgeTAM adds `timm` through `extra_packages`) and on
  `SegformerSegmenter` (`pytorch_model.bin`). `sam3_tracker` is declared
  `gated=True`.
- **TwinLiteNet+.** `TWINLITENET_REPO` (full commit
  `90f1b8695ae311d5123b05f8534b2e11e42499d2`), `repo: None` default, weights
  `UserProvided` with a "manual download" hint: the Drive command (small) or
  the upstream Drive folder `https://drive.google.com/drive/folders/1EqBzUw0b17aEumZmWYrGZmbx_XJqU-vz`
  (clone README line 87) for the other variants.
- **CLI.** `config_requirements(cfg)` returns `(path, name, type, req)` for each
  component plus `camera.estimate` (only when the depth model needs intrinsics
  and `camera.focal_estimate_config` says the estimate runs); `prepare_command`
  uses it. `prepare_command(cfg, root)` computes targets from
  `weights_root()`, so `root` must be that root (it is in `main`).
- **Configs.** No `hf_cache` (the anchors `&hf`/`*hf` are gone), bare YOLO
  names, no TwinLiteNet+ `repo`, comments without `~/dev` / `~/.roboflow`.
- **GPU tests (not run here).** `require_ready(config, overrides)` skips an
  example-config run until every declared model is ready (message names
  `--prepare`); the per-case asset table of the smoke is gone (the declarations
  replace it). `_missing_weights` looks for RF-DETR checkpoints under the
  weights root; adapter-contract fixtures keep their `DDD_*` explicit paths.
- **Security.** Asset targets come from `under_root` (resolved path inside the
  root) or fixed relative names; nothing outside the root is ever declared. Only a bare file
  name is joined to `<root>/ultralytics/` (`.`/`..` refused), so a relative
  path cannot climb through the weights root; paths with a directory part are
  resolved from the working directory, as the web path check resolves them.

## Final wave (task_0026)

Behaviour changed after review (see `docs/task_0026.md`):

- `known=True` only for canonical targets: `weights_asset` when the target is
  `ultralytics/<release name>`, `hf_asset` when the repo is in `HF_FACTS` and
  the cache is `<root>/hf`, the RF-DETR table and `TWINLITENET_REPO`. A
  release name at another in-root `weights` path or a known repo in another
  in-root `hf_cache` is prepared by the CLI only.
- `is_repo_id` checks the `org/name` shape (`REPO_ID_RE`, ASCII, no `..`)
  before probing the file system.
