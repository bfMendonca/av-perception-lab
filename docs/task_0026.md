# Task 0026: Model readiness final fix wave (COMPLETED)

## Description

The whole `feat/model_readiness` branch (tasks 0019-0025, head `d4b07e7`)
was reviewed twice (cross-task correctness and input validation of the
download/install surfaces). This task applies the fixes the reviews ask for
before merge. It hardens the owner's own software and removes one UX dead end:

- a model whose only missing file is a manual download (`UserProvided`) is
  offered as "Prepare", and Prepare / Prepare all always ends `failed`;
- an existing file whose size differs from the declared one (for example a
  fine-tuned checkpoint saved under a release file name) is downloaded over;
- `Asset.known` defaults to `True`, and the table-driven producers vouch for
  a client-chosen location (`weights`, `hf_cache`) as long as the file or repo
  name is known; the engine downloads unknown sources when the web queue runs
  a job;
- the web worker does not inherit `--weights-root`;
- URL downloads are not bounded by the expected size and do not check free
  disk space;
- some text sent to clients is not redacted or scrubbed, the scrub regex
  mangles prose ("basic requirements"), and `CodeRepo.describe_source` shows
  URL credentials;
- the weights root may be `/`, the home folder or a parent of the repository
  or the virtual environment;
- `is_repo_id` probes the file system with an unchecked client string;
- one test is flaky (1.0 s dry-run timeout);
- Prepare all starts multi-GB downloads with licences without a confirmation;
- the post-install "restart the server" note overstates what is needed.

Documentation (README "From a fresh clone", `docs/model_environments.md`,
`DESCRIPTION.md`, `CHANGELOG.md`, the task files of the changed behaviours)
is updated to match.

## Planning

### Step 1: Core (never overwrite, fail closed)

`known` defaults to `False`; producers set it for canonical targets only;
`UrlAsset.present` reports an existing mismatched file as `invalid`; the URL
source refuses to replace an existing target; the engine takes
`allow_unknown` and reports non-downloadable items as "provide this file".

### Step 2: Web (Prepare only what can be downloaded, confirm)

`user_provided` reason, Prepare all skips it, the queue runs the engine with
`allow_unknown=False`, the worker gets `DDD_WEIGHTS_ROOT`; the UI gets the
reason and a confirmation dialog before Prepare all.

### Step 3: Redaction, limits, root sanity

Redact boundaries, 422 redaction, scrub regex, dry-run messages, URL size
bound and free-disk check, weights root sanity (web and CLI), repo-id shape
check, flaky test, restart note.

### Step 4: Documentation

README, `docs/model_environments.md`, DESCRIPTION, CHANGELOG, "Final wave"
sections in the task files whose behaviour changed.

## Impact Analysis

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| A custom `weights` path with a release name stops being web-preparable | Medium | Intended (fail closed); the CLI still prepares it; message names `--prepare` |
| A user's existing mismatched file blocks Prepare | Low | Readable message: move or delete it, or point the config at another file |
| Weights root sanity refuses an existing setup | Low | Only `/`, home, and parents of the repo/venv/outputs are refused |
| Existing tests rely on `known=True` by default | Medium | Tests updated to declare `known=True` where they model a vouched source |

## Implementation details

Commits (branch `feat/model_readiness`):

1. `fix(core): never overwrite user files and fail closed on sources`
   - `core/requirements.py`: `Asset.known` / new `CodeRepo.known` default
     `False`; `UrlAsset.present` checks an existing target first: a file of
     another size or sha256 (or a folder) is `invalid` with "exists with a
     different size at <target> (...); move or delete it, or point the config
     at another file"; a `.part` alone is `partial`. `redact_root` boundary
     sets gain backtick, `<`, `>`, `{`, `}`. `CodeRepo.describe_source` is
     `git · host[:port]/path`. New `WEIGHTS_ROOT_ENV` and
     `weights_root_problem(root, others)` (`/`, home, a root containing the
     project folder, `sys.prefix` or `others`).
   - `core/provision/engine.py`: `prepare(..., *, allow_unknown=False)`;
     downloadable items with `known` False fail with `UNKNOWN_SOURCE` and
     their source never runs; a non-downloadable item's `ProvisionError` is a
     note (state stays `missing`); a transient dry-run failure in
     `install_packages` names `plan.message`.
   - `core/provision/sources.py`: `UrlSource` refuses an existing target
     before and after the download, bounds the body by
     `min(server length, declared size)` (removes the `.part`), checks
     `shutil.disk_usage` before writing.
   - `core/provision/packages.py`: scrub rules for `Authorization:` and a
     lone `Bearer`, `github_pat_`; "would install / would remove or replace"
     through `relative()`.
   - Adapters: `known=True` for the RF-DETR table, `TWINLITENET_REPO`,
     `weights_asset` only at `ultralytics/<name>`, `hf_asset` only for
     `HF_FACTS` repos in `hf`. `is_repo_id` applies `REPO_ID_RE` (ASCII,
     `org/name`, no `..`) before any `Path.exists`.
   - `cli.py`: `--prepare` passes `allow_unknown=True`; `main` refuses an
     unsafe weights root (with the config's `output.out_root`) with exit 2.
2. `fix(web): prepare only what can be downloaded and pass the weights root`
   - `web/models.py`: `user_provided_only`, reason `user_provided`,
     `UserProvidedOnly` (422), Prepare all skips such rows (and unknown
     sources) with their message; `unknown_sources` ignores non-downloadable
     kinds and checks `CodeRepo.known`; the queue runs the engine with
     `allow_unknown=False`; a weights job whose model only misses
     user-provided files succeeds (`ModelProgress.manual`); `client_text`
     (redact + `relative()` + scrub) for job exceptions; `INSTALLED_NOTE`.
   - `web/jobs.py`: `JobQueue(weights_root=...)` exports the absolute
     resolved root as `DDD_WEIGHTS_ROOT`; `web/app.py` passes it and
     redacts the four `str(exc)` 422 replies; `web/security.py` applies the
     core root sanity rule.
3. `fix(web): confirm Prepare all and show files the user must provide`
   - `ReadinessBanner.tsx`: `PrepareAllDialog` (ui/Dialog) with the
     downloads list, total and the "Files you must provide" note.
   - `api/models.ts`: `ModelReason` union with `user_provided`;
     `readiness.ts`: `isUserProvided`; `ModelRequirements.tsx`: the
     "provide it by hand" note; `useModelStatus.ts`: skipped toast uses the
     server's message; restart wording in the banner, the section note and
     the install dialog.
4. `docs: final fixes` (this file, README, DESCRIPTION, CHANGELOG,
   `docs/model_environments.md`, `docs/web_extending.md`, "Final wave"
   sections in task_0019-0024) plus one message fix found in the manual

Deviations from the brief:

- A complete target file next to a leftover `.part` is now `ready` (the
  target is judged first so that a mismatched file is never `partial`);
  `test_part_file_is_never_ready` was updated accordingly (a `.part` alone is
  still `partial`).
- An existing file whose **sha256** differs (or a folder at the target) is
  handled like a size mismatch (`invalid`, never replaced).
- The web also refuses to queue a *named* user-provided-only model (422,
  `UserProvidedOnly`), like a named unknown source.
- A weights Prepare job whose model fetched everything it could and only
  misses user-provided files ends `done` (no "Prepare failed" toast); the
  row then shows the hint.
- The CLI root sanity check includes the config's `output.out_root`; the
  video library is a web concept and is checked by the web server only.
- The "~9 GB" claim in `docs/model_environments.md` is sourced (the
  `_testbed/venv-infer` environment measured 9.0 GB with `du -sh`).
- Commit messages group the work by layer (core, web server, web UI, docs);
  intermediate commits were checked green for commit 1 only.
