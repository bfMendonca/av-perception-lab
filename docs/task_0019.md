# Task 0019: Model requirements declaration and torch-free status check (COMPLETED)

## Description

Today every adapter finds its weights in its own way (HF cache, run-time
download, a `.pt` path, `~/.roboflow`, a manual clone). A friend who clones the
repository cannot tell what is missing without reading code. This task is the
foundation of the "model readiness" work (spec
`docs/superpowers/specs/2026-10-31-model-readiness-design.md`): a framework-free
declaration of everything a component needs (weights, external code, Python
packages) and a status check that never imports torch.

Result: `core/requirements.py` with registered asset kinds (Hugging Face, URL,
user-provided), `CodeRepo`, `Requirements`, `ModelStatus`, `weights_root()` and
`check()`; and a `Component.requirements(options)` hook (default: empty).
This task also decides that new documentation and task files are in English, so
the template headings are translated and `AGENTS.md` gets one line saying so.

## Implementation details

- **What was done:** `core/requirements.py` holds `Asset` (frozen, kw_only
  base) with registered kinds `HuggingFaceAsset`, `UrlAsset` and `UserProvided`
  (`register_asset_kind`, `asset_kinds()`); each kind implements
  `present(root) -> AssetState` (ready / missing / partial / invalid plus a
  detail string), so `check()` only aggregates. `CodeRepo` (clone at
  `<root>/_code/<name>`, ready only when `git rev-parse HEAD` equals the pinned
  commit), `Requirements`, `ModelStatus`, `weights_root()` /
  `set_weights_root()` (setter, `DDD_WEIGHTS_ROOT`, repo `weights/`) and
  `check()`. `Component.requirements(options)` is a classmethod returning an
  empty `Requirements`. The template and `AGENTS.md` carry the English rule.
- **Rules enforced:** `.part` / `.incomplete` files and a size or sha256
  mismatch are `partial`, never ready; targets and clone names go through
  `contained()` (rejects `..`, absolute paths and symlinks leaving the root),
  and an unsafe declaration yields state `failed` with layer `invalid`;
  `UserProvided.downloadable` is `False`; packages are checked with
  `find_spec` on the top-level name only (nothing is imported).
- **Deviations from the plan:** asset fields `size_bytes` and `license` default
  to `None` (superset of the brief); `ModelStatus.layers` values may also be
  `partial` / `invalid`; `check` itself returns only `ready`, `missing` or
  `failed`, the other states are set by later layers. For the Hugging Face
  kind, `size_bytes` is a lower bound of the bytes found (patterns may match
  fewer files than the declared total).
- **Notes:** the Hugging Face kind reads the cache layout (`models--org--name/
  snapshots/<rev>/`, `refs/<revision>`, `blobs/*.incomplete`) without
  `huggingface_hub`. Hashing a large `UrlAsset` happens only when a sha256 is
  declared and the size matches.

- **Review fixes (round 1):** `check()` also catches `OSError`/`RuntimeError`
  (layer `partial`, "cannot inspect") and `ValueError` (layer `invalid`), so an
  unreadable folder, a symlink loop or a NUL byte never raises; the Hugging Face
  `revision` and the text of a `refs/` file must be plain names (no separators,
  `..`) and the snapshot must resolve inside the repo cache; `CodeRepo.name`
  must be a single plain path component; HF cache tests use real symlinked
  `blobs/` layouts; AGENTS.md and DESCRIPTION.md wording now says English
  (`(COMPLETED)`, `Implementation details`, `Test notebook`).

## Final wave (task_0026)

Behaviour changed after review (see `docs/task_0026.md`):

- `Asset.known` defaults to `False` (fail closed) and `CodeRepo` gained the
  same `known` field; adapters set it only for canonical targets.
- `UrlAsset.present`: an existing file whose size or sha256 differs from the
  declaration is `invalid` ("exists with a different size at <target>; move
  or delete it, or point the config at another file"), never `partial`; a
  matching file next to a leftover `.part` is `ready`.
- `redact_root` boundaries include backtick, `<`, `>`, `{`, `}`.
- `CodeRepo.describe_source` is `git · <host>/<path>` (no credentials or
  query).
- New `weights_root_problem(root, others)`: refuses `/`, the home folder and
  roots containing the project, the active environment or `others`.
